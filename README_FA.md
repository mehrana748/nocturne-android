# NOCTURNE — پلیر موسیقی آفلاین اندروید

**نسخهٔ توسعه:** 0.1.0 · **وضعیت:** پایهٔ بومی اپلیکیشن آماده شده؛ قابلیت‌های Music DNA و جداسازی استم هنوز به موتور واقعی وصل نشده‌اند.

NOCTURNE یک پروژهٔ بومی Kotlin + Jetpack Compose است که از طراحی تیره و پریمیوم نمونهٔ اولیه الهام می‌گیرد. هدف، ساخت پلیر آفلاین با کتابخانهٔ محلی و سپس افزودن تحلیل هوشمند موسیقی و جداسازی استم است.

## قابلیت‌های موجود در این نسخه

- رابط بومی اندروید با طراحی تیره، کاور آلبوم، صفحهٔ Now Playing، موج بصری و کنترل‌های پخش
- درخواست مجوز مناسب برای خواندن فایل‌های صوتی روی Android 13 و نسخه‌های قبل‌تر
- اسکن فایل‌های موسیقی فهرست‌شده در MediaStore گوشی
- پخش فایل محلی با AndroidX Media3 / ExoPlayer
- سرویس MediaSession برای ادامهٔ پخش در پس‌زمینه و یکپارچگی با کنترل‌های رسانه‌ای اندروید
- مرور کتابخانه بر اساس آهنگ، آلبوم یا هنرمند؛ صف بعدی/قبلی از همان فهرست یا فیلتر انتخاب‌شده پیروی می‌کند
- جست‌وجو در نام آهنگ، هنرمند و آلبوم
- خواندن ژانرهای نمایه‌شده در MediaStore و فیلتر آفلاین کتابخانه بر اساس ژانر
- جست‌وجو در اطلاعات آهنگ‌سازِ ایندکس‌شده در MediaStore (Android 11 به بعد)
- علاقه‌مندی‌ها با ذخیرهٔ محلی و ماندگار
- نمایش کاور آلبوم در صورت دسترس‌بودن در MediaStore
- تخمین آزمایشی BPM روی خود گوشی از حداکثر ۳۰ ثانیهٔ آهنگ در حال پخش، با ذخیرهٔ نتیجه در کش محلی
- فیلترهای تقریبی کند/میانه/تند برای آهنگ‌های دارای BPM ذخیره‌شده
- ساخت، ذخیره، تغییر نام، مرتب‌سازی دستی یا خودکار و حذف پلی‌لیست‌های هوشمند محلی با ترکیب قانون‌های علاقه‌مندی، ژانر و BPM؛ نتایج پویا هستند
- ساختار اولیهٔ محلی برای ذخیرهٔ متادیتای افزوده‌شده در آینده
- قراردادهای نرم‌افزاری مشخص برای متصل‌کردن سرویس شناسایی متادیتا و موتور جداسازی استم

## مواردی که هنوز پیاده‌سازی نشده‌اند

- شناسایی آنلاین آهنگ با Audio Fingerprinting و اتصال به AcoustID / MusicBrainz
- ارزیابی دقت تخمین BPM روی مجموعهٔ آهنگ‌های مرجع؛ تحلیل محلی گام، آکورد، انرژی و تشخیص ساز هنوز پیاده‌سازی نشده است
- تغییر نام و مرتب‌سازی دستی پلی‌لیست‌های هوشمند
- جداسازی واقعی Vocals / Drums / Bass / Other و مدل‌های پیشرفتهٔ سازمحور
- خروجی گرفتن از استم‌ها، میکسر استم‌ها و مدیریت فایل‌های خروجی
- تست روی مجموعه‌ای از گوشی‌های واقعی و آماده‌سازی انتشار در Google Play

صفحهٔ **Music DNA** ژانرهای نمایه‌شدهٔ محلی و تخمین آزمایشی BPM را نشان می‌دهد؛ شناسایی آنلاین آهنگ و تحلیل گام/ریتم هنوز وصل نشده‌اند. صفحهٔ **Stem Lab** نیز وضعیت واقعی موتور جداسازی را نشان می‌دهد و ادعا نمی‌کند که جداسازی هوش مصنوعی انجام شده است.

## ساخت APK قابل نصب

### راه اول: ساخت خودکار با GitHub Actions (پیشنهاد برای گرفتن APK بدون نصب Android Studio)

1. این پوشه را در یک مخزن GitHub قرار بده.
2. از تب **Actions** گردش‌کار **NOCTURNE Android APK** را باز کن.
3. گزینهٔ **Run workflow** را اجرا کن یا یک commit به شاخهٔ `main` / `master` بفرست.
4. بعد از موفقیت، از بخش **Artifacts** مورد `nocturne-android-debug-apk` را دانلود کن.
5. فایل `NOCTURNE-0.1.0-debug.apk` را به گوشی انتقال بده و نصب کن. ممکن است اندروید اجازهٔ نصب از منبع فایل را جداگانه بخواهد.

این APK برای تست روی گوشی و نصب مستقیم ساخته می‌شود و با کلید debug امضا می‌شود؛ برای انتشار Google Play باید نسخهٔ release، کلید امضای امن و فرایند انتشار جداگانه تنظیم شود.

### راه دوم: ساخت در Android Studio

1. آخرین نسخهٔ Android Studio و JDK 17 را نصب کن.
2. پوشهٔ `nocturne-android` را باز کن.
3. Android SDK Platform 36 و Build Tools 36.0.0 را نصب کن.
4. Gradle Sync را اجرا کن و اجازه بده وابستگی‌ها از اینترنت دریافت شوند.
5. از مسیر **Build → Build APK(s)** نسخهٔ آزمایشی را بساز.
6. خروجی Debug معمولاً در مسیر `app/build/outputs/apk/debug/app-debug.apk` قرار می‌گیرد.

پروژه برای Gradle 8.13 و Android Gradle Plugin 8.11.1 تنظیم شده است. ساخت Debug APK از طریق GitHub Actions در commit فعلی با موفقیت تأیید شده است. فایل `NOCTURNE-0.1.0-debug.apk` از بخش **Artifacts** اجرای موفق گردش‌کار قابل دریافت است. نصب و آزمایش پخش روی گوشی واقعی هنوز انجام نشده است.

## حریم خصوصی و معماری

- اسکن فعلی فقط MediaStore محلی دستگاه را می‌خواند؛ فایل صوتی در این نسخه جایی آپلود نمی‌شود.
- هیچ کلید API یا سرویس پولی در پروژه تعبیه نشده است.
- برای شناسایی متادیتا باید سرویس قانونی و شرایط استفادهٔ تجاری بررسی شود. اثر انگشت صوتی باید به‌جای ارسال بی‌دلیل فایل کامل ترجیح داده شود، در صورتی که سرویس و فرمت مورد استفاده اجازه دهند.
- جداسازی استم قبل از انتشار باید با مدل و مجوز تجاری سازگار انتخاب و روی گوشی واقعی از نظر RAM، گرما، مصرف باتری، سرعت و کیفیت ارزیابی شود.

## معماری پوشه‌ها

- `MainActivity.kt` — رابط کاربری، مجوز، وضعیت کتابخانه و کنترل‌های پخش
- `data/LocalLibraryScanner.kt` — اسکن MediaStore
- `data/FavoritesStore.kt` — ذخیرهٔ علاقه‌مندی‌ها
- `data/MetadataStore.kt` — کش محلی متادیتای افزوده‌شده
- `data/AudioIntelligenceContracts.kt` — رابط اتصال سرویس متادیتا و موتور استم
- `playback/MusicPlaybackService.kt` — پخش Media3 و MediaSession در پس‌زمینه

## گام‌های بعدی پیشنهادی

1. Build، رفع خطاهای احتمالی و تست اسکن و پخش روی گوشی واقعی.
2. افزودن تست‌های فرمت‌های رایج (MP3، AAC/M4A، FLAC، Ogg) و پوشه‌های چندرسانه‌ای.
3. افزودن لایهٔ Music DNA: تطبیق اثر انگشت، ذخیرهٔ منبع/میزان اطمینان و صف تحلیل با محدودیت نرخ؛ اعتبارسنجی تخمین BPM و تحلیل گام/ریتم.
4. افزودن تحلیل صوتی محلی و پلی‌لیست‌های هوشمند.
5. افزودن موتور جداسازی استم پس از بنچمارک مدل‌ها و بررسی مجوزهای تجاری.
